How to prepare a supplier CSV for import

A CSV can look tidy in a spreadsheet while still having repeated headers, a short row or columns in the wrong order. Work on a copy of the supplier file and get the destination's current import template before editing. The examples here are invented inventory data.

Start with the file structure

Use CSV Import Checker to find repeated headers, quoting problems and unexpected field counts. These checks do not verify prices, stock levels or your importer's business rules.

Check a CSV before importing

1. Find the duplicate header and short row

Download the original sample CSV (2 deliberate issues). Use Open a CSV file in the checker, or paste the example below. These samples contain invented data and are for practice.

Paste this comma-separated example into the checker and select Check CSV:

SKU,Product,Price,Price
A101,"Mug, blue",12.00,8.00
A102,Notebook,6.50
A103,"Frame, small",15.00,9.50

It reports two issues: Price repeats in columns 3 and 4, and line 3 has only three fields instead of four. The comma inside "Mug, blue" belongs to the product name because that field is quoted.

Select Download check report (.txt) to keep the issue locations and suggested fixes. The report should say Issues found. It records the check; it does not repair the source file.

2. Correct the data using the supplier's meaning

Download the corrected sample CSV to compare it with your edits.

For this example, assume the supplier confirms the fourth column is Cost and the Notebook's missing cost is 4.00. Make those corrections in a copy:

SKU,Product,Price,Cost
A101,"Mug, blue",12.00,8.00
A102,Notebook,6.50,4.00
A103,"Frame, small",15.00,9.50

Check the corrected CSV again. It should pass the header and field-count checks with four columns and three data rows. Select Download corrected CSV to save the checked text for the next step. For a real file, confirm missing values with the supplier; do not invent them or insert zero just to make the row pass. A blank field is appropriate only when its meaning and the destination allow it.

Download a fresh check report after rechecking: its status should now be Passed. Editing the CSV invalidates the previous download until you run the check again.

3. Map columns to the destination

Open CSV Column Mapper. Paste the corrected CSV and use this illustrative destination header:

SKU,Title,Price

Select Set up mapping, then map SKU → SKU, Product → Title and Price → Price. The Cost column is deliberately excluded. Select Build mapped CSV; the first data row should be:

A101,"Mug, blue",12.00

Use the exact header from your actual destination rather than assuming these three example fields are sufficient. Review every selection, including any Use empty values choice. Download the full CSV: the preview shows only the first five data rows. The mapper accepts UTF-8 comma-separated CSV input up to 2 MiB.

Review the mapping summary and save its report

After building, review Mapping summary. This example should show 3 input and 3 output data rows, four source columns and three destination columns. Product → Title is renamed; source column 4, Cost, is omitted. The table also identifies moved columns and any source reused in more than one destination. Counts exclude the header, and data-row order is preserved.

Select Download mapping report (.txt) to save csv-mapping-report.txt beside mapped.csv. The report describes the prepared export and includes headings, mapping choices and counts, but no product-row contents. Review headings before sharing. Changing the source, destination, column choices or loading a mapping clears the report and CSV until you build again. Download both again after changes.

To practise empty-value mapping, use Title,SKU,Optional as the destination header. Map Product → Title, SKU → SKU and choose Use empty values for Optional. Expect three output rows, two omitted source columns (Price and Cost), and three inserted blank cells. These counts do not include blanks already present in source cells. Only use an empty destination when your importer accepts it. Restore SKU,Title,Price and its original mapping before continuing with the example below.

This is a mapping record, not a formula-safety or importer-acceptance certificate. Check the exact exported CSV in the next steps.

Check required values without changing the export

Tick Required value for each destination column your importer requires, then select Build mapped CSV. For the corrected example, select SKU, Title and Price: expect Passed, with no missing values across three data rows. Unticked columns are not checked. With no selected columns, or with only a header and no data rows, the result says Not checked.

Download the required-field practice CSV. Map SKU to SKU, Product to Title and Price to Price, and mark all three required. Expect 3 missing values across 3 data rows: SKU in data row 2, Title in data row 3 (spaces only), and Price in data row 4. Their CSV record numbers and source/mapped line numbers are 3, 4 and 5. The first row's price of 0 is present and should not be flagged. 0.00 also counts as present; this is a presence check, not a price-range rule.

The on-page findings and mapping report identify the destination column, data row, CSV record and start line in both the source and mapped CSV. Data rows exclude the header; records include it. Source and mapped line numbers can differ when multiline fields are omitted or reordered. All rows are checked; the page and report list up to 100 findings and show the full total.

Checks do not trim, fill, remove or otherwise alter values: the mapped CSV is identical with the same mapping whether required checks are on or off. Downloads remain available when issues are found so you can save and correct the file. Confirm missing values with the supplier, fix a copy, then rebuild and download a fresh CSV and report. A passing presence check does not verify numeric ranges, unique identifiers, formula safety or importer acceptance.

Changing a required choice clears the previous result until you rebuild. Required choices start off with a new setup, source CSV, destination text or sample. Save mapping includes your required-field choices; Load mapping restores them for the destination columns, even when source columns are reordered. Older version 1 mappings still load, with every required choice off and a reminder to review them. Return to the corrected sample and check your required fields before continuing.

Save the mapping for your next supplier file

  1. Once all source choices are selected, choose Save mapping to download utilityshelf-column-mapping.json. The version 2 file contains source and destination headings, column selections and a required/not-required choice for each destination, with no product rows.
  2. Next time, open or paste the new supplier CSV, select Load mapping, and choose that JSON file. The destination headings and required-field choices are restored. A source column moving does not move a required choice to a different destination.
  3. Review every source choice and required checkbox, then select Build mapped CSV. Loading a mapping does not automatically create an export.

Columns may change order: the mapper follows their exact header names. If a header is added, removed, renamed or changed in case or spacing, loading stops and asks you to set up a fresh mapping. Duplicate or blank source headers cannot be used in reusable mappings. This protects against silently selecting a different column. Header matches do not prove that a supplier has kept the same field meanings or units. Invalid mapping files (including missing, malformed or mismatched required-field choices in version 2) are rejected; no previous export or report remains available. Files saved by this version require the updated mapper; older version 1 files remain supported.

4. Review formula-like values in the export

Open the downloaded file in CSV Formula Checker. A value such as "=SUM(2,3)" can become a formula when opened in a spreadsheet even though the CSV quotes are correct. A flag may also be legitimate data, such as a negative amount.

The checker flags prefixes; it does not sanitise the file. Review the intended values and your spreadsheet's text-import settings. Do not assume that adding quotes makes a CSV safe. See OWASP's CSV formula-injection guidance for application-specific limitations.

Select Download check report (.txt) to save the formula review. The mapped corrected example has three columns and three data rows: expect 0 fields to review out of 12 checked, including the header. For a deliberate warning, change the Notebook title in a practice copy to =SUM(2) and rescan; the report should identify record 3, line 3, column 2.

The two checker reports use Passed, Issues found or Check incomplete. An incomplete check, for example from a missing closing quote, is not a pass. Reports list up to 100 findings and state when more were found. They can include header names or field previews, so review them before sharing. Keep reports alongside the exact CSV you checked and rerun after changes.

5. Check the final saved file

  1. Run CSV Import Checker on the exact export you intend to import, especially after making corrections.
  2. Confirm required fields, currencies, decimal separators, identifiers and stock values against the destination's specification.
  3. Keep identifiers such as 0012 as text if opening the file in a spreadsheet, so leading zeros are not lost.
  4. Use the destination's preview or a small test import first and compare its results with your source records.

Choose or paste the file in each tool separately; the tools do not transfer data between tabs. A passing structure check and no formula-prefix flags do not guarantee a successful import.
